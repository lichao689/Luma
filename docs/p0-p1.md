# P0 / P1 implementation and acceptance

This work implements the six directions requested in the Luma project conversation. The baseline is commit `d122d3e6f10e77bffe19d523b4d51682146fc060`. Changes are developed on `codex/luma-p0-p1-20261126` and must be reviewed before merging.

## Scope and observable behavior

| Priority | Direction | Acceptance |
| --- | --- | --- |
| P0 | Recovery-aware recommendation | Explicit rest and discomfort take precedence; weekly goals and daily caps agree; partial training affects recovery without becoming a full goal; dates and muscle overlap are considered; reasons explain the choice. |
| P0 | Guided workout and custom plans | Choose an 8/15/25-minute budget, edit/save/load a plan, replace compatible movements, reorder sets of exercises, pause/resume, record actual repetitions or hold seconds, and save completed sets after stopping early. |
| P1 | History | View daily activity and minutes for 7/30/90 days; inspect exercise load/repetition/hold trends without mixing units; handle empty data; delete with confirmation. |
| P1 | Apple Health | An iPhone helper requests read-only workout/steps/sleep access and exports a versioned file. Mac imports after preview, deduplicates source UUIDs, preserves absent data, and maps only running workouts to the running goal. |
| P1 | Progression | Use complete per-exercise histories, including incomplete sessions. Suggest a conservative load change only with sufficient evidence, explain it, and require acceptance. Never replace actual results with target values. |
| P1 | Backup and cross-device sync | Versioned JSON preserves sessions, actual sets, goals, plans, health imports, and deletion markers. Restore previews changes, rejects conflicting identity, and rolls back failed saves. Manual shared-folder sync uses independent device snapshots; CSV has explicit units. |

## Product decisions

- A single workout coordinator owns the current session. Closing the window pauses it; reopening resumes the same in-memory session. Quitting warns before discarding unsaved work. Process crash recovery is not provided.
- New profiles default to three strength sessions per week. Existing saved goals are preserved. A daily strength target is a training-day cap, not a demand to train every day.
- Recovery intervals, duration × reported effort, and progression limits are transparent software heuristics. They are not physiological measurements or personalized medical prescriptions. `RecommendationPolicy` and `ProgressionPolicy` expose the parameters for review and testing.
- Plan duration is a volume budget and estimate. Users control their pace and may extend rest. A sleeping Mac cannot silently complete multiple exercises: system sleep pauses the current session, and the state machine never auto-starts the next set.
- Repetitions require actual user input. Timed holds record elapsed seconds. Left/right sides and units survive storage, backup, import, and CSV export.
- Saving a session and its sets is one transaction. Retrying the same UUID and contents is a no-op. Conflicting content is an error; it is never silently overwritten.
- Native macOS does not read the iPhone Health store directly. The small iOS helper exports only after a user action; the Mac importer has its own preview and confirmation. See [healthkit-bridge.md](healthkit-bridge.md).
- Multi-device sync in this version means **manual cross-Mac shared-folder sync**. Choose the same iCloud Drive or shared folder on each Mac and click preview/confirm. It is not automatic CloudKit replication, and Luma supplies no cloud server. The folder provider handles transport and access. A sync snapshot contains health data if any has been imported.
- Restore preserves local goals unless the user explicitly selects the backup goals. Folder sync shows differences and retains local preferences. Explicit deletion markers prevent an older device or backup from resurrecting deleted records.
- Reminder escalations are cancelled and rechecked when settings, work windows, meetings, training, snooze, or intentional rest change. Notification buttons open guided exercise, snooze, or record rest as labelled.

## Validation

The integrated portable suite passed **131 tests with zero failures** using Swift 6.0.3 on Linux during this implementation. Portable logic tests run with `swift test --package-path LogicPackage`. The macOS app and SwiftData integration tests require Xcode:

```sh
xcodebuild test -project OfficeWorkoutCoach.xcodeproj -scheme OfficeWorkoutCoach -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO
xcodebuild build -project HealthBridgeIOS/LumaHealthBridge.xcodeproj -scheme LumaHealthBridge -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO
```

`.github/workflows/apple-validation.yml` performs these checks on a macOS runner for pull requests. Successful compilation does not validate notification delivery, actual Health authorization, iCloud propagation, or physical exercise instruction.

## Device acceptance before release

1. Open an existing installation with prior sessions and verify migration, goals, and historical sets. Export a full backup first.
2. Open a plan, edit it, save a copy, reorder and replace an exercise, then run the plan. Complete an actual repetition set and a timed unilateral exercise. Pause, close and reopen, sleep/wake, stop early, and save. Verify exactly one session and the correct sides/units.
3. Attempt a second workout while one is open. It must return to the current session. Quit with unsaved work and confirm that cancellation preserves it.
4. View 7/30/90-day charts, no-data states, and exercises with only seconds or only repetitions. Delete a test session and verify its sets disappear.
5. Export, restore into a clean profile, restore the same file twice, and attempt a conflicting/corrupt/oversized import. Confirm no duplicate rows or partial changes.
6. On two Macs, preview and publish device snapshots. Confirm both converge after importing each other's latest snapshot, a deletion survives an older snapshot, and differing goals do not overwrite local settings.
7. Sign the iOS helper with the user's Apple team. On an iPhone, grant some/none/all requested read permissions, export, and import on Mac. Reimport overlapping periods; test explicit workout deletion and sleep overlap. Denied or absent data must not appear as known zero.
8. Verify notification Start/Later/Rest actions with the popover closed. Start training or a meeting during escalation, leave the work window, disable reminders, or snooze: no delayed speech/dialog should fire.
